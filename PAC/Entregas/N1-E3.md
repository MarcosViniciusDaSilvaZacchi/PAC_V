### 2. Detalhamento das User Stories e Critérios de Aceite (DoD / AC)

#### US01: Cadastro de Professores
- **Descrição:** Como administrador, quero cadastrar professores para que possam acessar o sistema.
- **Critérios de Aceite:**
  - O administrador deve informar nome completo, e-mail institucional/válido e definir a senha inicial ou envio de link de ativação.
  - O sistema não permite cadastro de e-mails duplicados.
  - O professor recém-cadastrado é associado automaticamente ao perfil professor.

#### US02: Cadastro de Disciplinas
- **Descrição:** Como professor, quero cadastrar disciplinas para organizar meus materiais por turma.
- **Critérios de Aceite:**
  - O professor informa o nome da disciplina (ex: *Português Básico I*) e descrição/horário.
  - A disciplina criada fica vinculada automaticamente ao ID do professor autenticado.
  - Apenas o professor responsável ou o administrador podem alterar as informações da disciplina.

#### US03: Vinculação/Matrícula de Alunos
- **Descrição:** Como professor, quero cadastrar alunos em uma disciplina para controlar quem tem acesso aos materiais.
- **Critérios de Aceite:**
  - O professor pode cadastrar novos alunos ou vinculá-los à disciplina por e-mail/identificador.
  - O sistema associa o aluno à disciplina através de um registro na entidade Matricula.
  - O aluno cadastrado recebe acesso imediato às disciplinas em que foi matriculado.

#### US04: Upload de Materiais Didáticos em PDF
- **Descrição:** Como professor, quero inserir materiais em PDF em uma disciplina para disponibilizá-los aos alunos.
- **Critérios de Aceite:**
  - O sistema aceita exclusivamente arquivos no formato .pdf.
  - Validação de tamanho máximo de arquivo (ex: até 15MB por PDF).
  - O arquivo é persistido no Object Storage e a URL/metadados registrados no banco de dados.

#### US05: Edição/Substituição de Materiais Didáticos
- **Descrição:** Como professor, quero editar ou substituir um material já inserido para manter o conteúdo atualizado.
- **Critérios de Aceite:**
  - O professor pode renomear o título do material ou fazer upload de uma nova versão do PDF.
  - O sistema atualiza o registro mantendo a associação com a disciplina e gravando tualizado_em.
  - O arquivo antigo substituído é removido ou versionado no storage para otimizar espaço.

#### US06: Visualização de Materiais pelo Aluno
- **Descrição:** Como aluno, quero visualizar os materiais da minha disciplina para estudar fora do horário de aula.
- **Critérios de Aceite:**
  - O aluno visualiza apenas as disciplinas nas quais possui matrícula ativa.
  - A interface deve oferecer visualizador embutido de PDF ou link para download direto, adaptado a dispositivos móveis.
  - Alunos não matriculados ou usuários não autenticados não têm permissão para acessar os arquivos.

#### US07: Acesso à Cartilha Informativa Digital
- **Descrição:** Como aluno, quero acessar a cartilha informativa digital para consultar informações de apoio quando precisar.
- **Critérios de Aceite:**
  - A cartilha deve estar acessível por um botão/atalho em destaque na área do aluno.
  - Abertura rápida no navegador, sem etapas intermediárias complexas.
  - Administradores ou professores podem publicar versões atualizadas da cartilha.

#### US08: Autenticação e Gestão de Sessão (Login)
- **Descrição:** Como usuário, quero fazer login no sistema para acessar apenas as funcionalidades do meu perfil.
- **Critérios de Aceite:**
  - Autenticação via e-mail e senha com hash seguro (crypt).
  - Geração de token JWT com payload contendo ID e papel do usuário (dmin, professor, luno).
  - Redirecionamento automático para a dashboard correspondente ao perfil após login com sucesso.
  - Mensagens claras e amigáveis em caso de erro de credenciais.

#### US09: Controle de Permissões e Acesso Baseado em Perfis (RBAC)
- **Descrição:** Como administrador, quero que apenas admin e professor consigam editar conteúdo, para preservar a integridade dos materiais.
- **Critérios de Aceite:**
  - Endpoints da API que alteram estado (POST, PUT, DELETE) validam via middleware se a role é dmin ou professor.
  - Usuários com perfil luno possuem permissão estrita de consulta/leitura (GET) nos materiais liberados.
  - Tentativas de acesso não autorizado retornam código HTTP 403 Forbidden.

### 3. Planejamento Front-end

- **Framework:** Vue.js 3 com Composition API (<script setup>) para código desacoplado e manutenível.
- **Roteamento:** Vue Router com guardas de navegação por perfil de acesso (dmin, professor, luno).
- **Gerenciamento de Estado:** Pinia (stores modulares para autenticação/sessão, disciplinas ativas e cache de materiais).
- **Estilização e Responsividade:** Tailwind CSS com abordagem **Mobile-First**, priorizando clareza visual e facilidade de toque para celulares simples.
- **Comunicação com a API:** Axios com interceptors para anexar o token Bearer JWT e interceptar códigos HTTP de erro (401/403).

---

### 4. Planejamento Back-end

- **Runtime & Framework:** Node.js (v20+ LTS) com framework Express, adotando arquitetura em camadas (Controllers, Services, Repositories).
- **Autenticação & Segurança:** JSON Web Tokens (JWT) com expiração configurável, hash de senha com crypt e middlewares de controle de acesso (RBAC).
- **Camada de Persistência:** ORM Sequelize mapeando entidades em PostgreSQL, com migrações versionadas (migrations) e sementes (seeders).
- **Upload de Arquivos:** Middleware multer para processar uploads de PDFs, com validação de tipo de arquivo (MIME type) e limite de tamanho.
- **Validação de Entrada:** Schemas com Zod ou Joi em todas as rotas da API.

---

### 5. Planejamento de Infraestrutura e DevOps

- **Front-end:** Hospedagem em serviço de deploy estático/SPA com CDN global (Vercel / Netlify).
- **Back-end:** Container gerenciado / PaaS (Render / Railway), com reinício automático e variáveis de ambiente isoladas.
- **Banco de Dados:** Instância gerenciada de PostgreSQL na nuvem, com políticas de backup diário.
- **Armazenamento de Arquivos:** Object Storage compatível com S3 (AWS S3, Cloudflare R2 ou Supabase Storage).
- **CI/CD:** Pipelines no GitHub Actions para validação de sintaxe, testes e deploy contínuo em cada push na branch main.
- **Segurança:** Comunicação integralmente sob HTTPS/TLS e proteção contra ataques comuns (Helmet, CORS restrito).

### 2. Dicionário de Dados e Entidades

#### Usuario
Representa qualquer indivíduo com credenciais de acesso ao sistema.
- id (PK, Inteiro auto-incremental): Identificador exclusivo do usuário.
- 
ome (VARCHAR, obrigatório): Nome completo do usuário.
- email (VARCHAR, obrigatório, UNIQUE): E-mail de autenticação e comunicação.
- senha_hash (VARCHAR, obrigatório): Hash criptográfico da senha (bcrypt).
- perfil (ENUM/VARCHAR: 'admin', 'professor', 'aluno', obrigatório): Define o nível de permissão e papel do usuário.
- data_cadastro (TIMESTAMP): Data e hora em que o usuário foi registrado.

#### Disciplina
Representa uma turma/disciplina do curso do projeto (ex: Português Nível Básico).
- id (PK, Inteiro auto-incremental): Identificador da disciplina.
- 
ome (VARCHAR, obrigatório): Título descritivo da matéria/turma.
- descricao (TEXT, opcional): Resumo dos objetivos ou calendário da disciplina.
- professor_id (FK referenciando Usuario.id): Professor responsável pela disciplina.
- criado_em (TIMESTAMP): Data e hora de criação da turma.

#### Matricula
Entidade associativa que implementa a relação N:N entre alunos e disciplinas.
- id (PK, Inteiro auto-incremental): Identificador do registro de matrícula.
- luno_id (FK referenciando Usuario.id): Usuário com perfil de aluno matriculado.
- disciplina_id (FK referenciando Disciplina.id): Disciplina à qual o aluno está associado.
- data_matricula (TIMESTAMP): Momento em que a matrícula foi efetivada.

#### Material
Representa os arquivos didáticos e complementares anexados a uma disciplina.
- id (PK, Inteiro auto-incremental): Identificador do material.
- 	itulo (VARCHAR, obrigatório): Título ou nome de apresentação do documento.
- rquivo_pdf (VARCHAR, obrigatório): URI/caminho do arquivo PDF no Object Storage.
- disciplina_id (FK referenciando Disciplina.id): Disciplina a que pertence o material.
- data_upload (TIMESTAMP): Data de disponibilização inicial do PDF.
- tualizado_em (TIMESTAMP): Data da última modificação ou substituição do PDF.

#### Cartilha
Recurso institucional autônomo disponível para consulta de todos os alunos do projeto.
- id (PK, Inteiro auto-incremental): Identificador da cartilha.
- 	itulo (VARCHAR, obrigatório): Nome da cartilha (ex: *Cartilha Informativa do Imigrante*).
- rquivo_pdf (VARCHAR, obrigatório): URI do documento em PDF no Object Storage.
- ersao (VARCHAR): Identificador de versão da edição publicada.
- data_publicacao (TIMESTAMP): Data de lançamento da versão no sistema.

### 3. Regras de Integridade Referencial
- **Exclusão de Disciplina:** Deve cascatear (CASCADE) ou restringir (RESTRICT) os registros vinculados em Material e Matricula.
- **Exclusão de Aluno:** Exclui as referências correspondentes na tabela associativa Matricula.
- **Unicidade de E-mail:** Garante que cada usuário possua acesso unívoco na base de dados.
- **Isolamento da Cartilha:** Não depende de turmas nem disciplinas, servindo como documento de apoio global.
